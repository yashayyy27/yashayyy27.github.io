01 / The decision

Which loss deserves attention?

A large percentage drop is not automatically the largest commercial opportunity. An analyst must define the denominator, confirm collection, compare absolute and proportional losses, and distinguish an observation from a causal explanation.

The decision to support

Prioritise one measurement or product investigation, explain competing hypotheses, and specify the evidence needed before authorising a controlled experiment or a media-budget change.

02 / The engineering

Make the path inspectable.

  1. Collect with consent. The imaginary store emits eight schema-validated events. GTM loads only after analytics consent; advertising consent remains denied. Actual unpublished Preview events were matched in the owner's GA4 DebugView, including two distinct test purchases.
  2. Reconcile the grains. Fixed read-only SQL establishes event, session and transaction measures. A complete public GA4 extract is compared with an independent GoogleSQL aggregation, with explicit date, timezone, currency and completeness checks.
  3. Constrain the analyst. An optional Responses provider offers six registered tools plus abstention, structured output and an exact evidence gate. No arbitrary SQL is generated. SDK protocol tests and fixture evaluations are labelled separately from live model quality.
  4. Carry the decision to the client. The six-slide PDF combines provenance, funnel analysis, competing explanations, one recommendation and an experiment plan. Editing resets the review flag. The committed example remains a draft, not client approval.

03 / A genuine public-data analysis

Reconciliation before interpretation.

Three authenticated, unbilled BigQuery Console jobs queried Google's public obfuscated GA4 ecommerce dataset for 1 January 2021, UTC. All 22,096 events were extracted and all nine SQL/local checks matched. This is historical public data, not current client traffic.

Separately, the transaction grain reconciled 13 distinct transactions and USD 961 recorded revenue. Transactions and ordered purchasing sessions have different definitions; their difference does not establish a tracking defect.

Session → product view loses 86.28% of started sessions. That is the first diagnosis priority, not a forecast of recoverable revenue.

Recommendation: validate product-reach measurement and landing intent before changing checkout or reallocating media. Non-shopping intent, obfuscation, boundary-session truncation, missing event sequences and genuine discovery friction are competing explanations. This extract cannot distinguish them.

Proposed experiment: after measurement QA and a stable baseline, test whether clearer product discovery improves eligible-user progression. Predeclare the assignment unit, minimum meaningful effect, sample-size assumptions, purchase/revenue guardrails and decision rule. No experiment or uplift is claimed. Spend and matched touchpoints are unavailable, so ROAS and causal attribution are withheld.

04 / A failure and a repair

Test what should be rejected.

An adversarial fixture replaced a required metric with two near-equal copies of another. The original evidence validator accepted it. Replaying the same candidate after enforcing exact metric-identity completeness produced a rejection. The original accepted result and corrected rejection are preserved in the repository.

A separate browser regression reproduced a saved-consent race on both desktop and mobile: initial events could enter the queue before consent restoration. Moving restoration ahead of child event effects made the unchanged regression pass. These are observed software failures and repairs, not invented failed model answers.

Verification: 72 Python tests, 50 frontend tests and 16 browser tests passed in the recorded release, including automated accessibility scans on all seven pages. Hosted CI also passed.

Evaluation boundary: deterministic development cases improved from 21/36 to 36/36; the inspected release set passed 24/24. No authenticated LLM evaluation was run, so none of these scores measures model quality.
